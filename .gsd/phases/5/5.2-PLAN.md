# Plan 5.2: Docker Compose Setup

## Objective
Provide standard Docker infrastructure for the project so that any user can spin up the full stack via a single command.

## Context
- .gsd/SPEC.md
- ui/app.py

## Tasks

<task type="auto">
  <name>Backend Dockerfile</name>
  <files>Dockerfile</files>
  <action>
    - Create a standard Python `Dockerfile` in the root.
    - Set working directory to `/app`.
    - Copy `requirements.txt` and install dependencies.
    - Copy backend folders (`app.py`, `routes`, `rag`, `utils`, `memory`).
    - Expose port 5000 and run `flask run --host=0.0.0.0 --port=5000`.
  </action>
  <verify>Run `docker build -t ai-study-backend .` successfully.</verify>
  <done>Backend image builds without errors.</done>
</task>

<task type="auto">
  <name>Frontend Dockerfile & Compose</name>
  <files>ui/Dockerfile, docker-compose.yml, ui/app.py</files>
  <action>
    - Modify `ui/app.py` to use `API_BASE = os.getenv('API_BASE', 'http://localhost:5000')` for dynamic mapping. Include `import os`.
    - Create `ui/Dockerfile`. Copy `requirements.txt` from the parent directory context (assuming build context is root) or define how to run Streamlit on port 8501.
    - Create `docker-compose.yml` in the project root defining `backend` (port 5000) and `frontend` (port 8501).
    - In the `frontend` service, set environment variable `API_BASE` to `http://backend:5000`. Include `GEMINI_API_KEY` pass-through on `backend`.
  </action>
  <verify>Visually review the `docker-compose.yml` structure for correctness of ports and ENV variables.</verify>
  <done>Multi-container configuration is defined properly.</done>
</task>

## Success Criteria
- [ ] Both Backend and Frontend encapsulate all dependencies into standard Dockerfile definitions.
- [ ] Inter-service communication relies on Docker DNS.
